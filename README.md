# 艾搭 AIDA · 从你的游戏行为里长出来的 AI 搭子

> **单排太孤独了。所以我做了一个会陪打、会记仇、会一起翻盘的 AI 搭子。**

## 为什么做这个

某个凌晨，连败第三把之后我盯着结算界面想：游戏里最孤独的几个小时，恰恰是所有 AI 陪伴产品缺席的地方——它们都在聊天框里，没有一个是陪着打游戏的。

所以我动手做了艾搭：她看你的每一场对局，**只在你倒下、结算、喘息的间隙开口**；她记得你们一起翻过的盘，也记得谁把你打崩过。玩得越久，她的性格越像你的老搭子——因为关系不是聊出来的，是一起挨打、一起翻盘攒出来的。

## 这是什么

一套「可捏、可养、可陪伴」的 AI 游戏伙伴产品原型：

- **多伙伴**：8 位性格迥异的预设搭子——男生向（损友·艾搭 / 御姐·纪岚 / 甜妹·小满 / 假小子·阿野），女生向（闺蜜·小暖 / 奶狗·岁岁 / 男神·闻笙 / 体育生·一鸣）；或亲手捏一个专属搭子
- **共同经历**：搭子陪你回放真实职业比赛（开源数据），时机引擎保证团战正酣时绝不出声
- **成长闭环**：经历沉淀为情绪记忆（高光/至暗/习惯/里程碑）→ **性格五轴随经历演化**（可解释、可审计、玩家可在边界内塑形）→ 关系从「初识」处到「过命战友」
- **全场景陪伴**：文字聊天 + 语音（TTS 音色随性格变化 / STT 按住说话）+ 桌面置顶小窗（Document PiP 真桌宠）
- **虚拟形象**：程序化 SVG 形象，表情随情境变化，配色/发型/配件可编辑

## 三分钟体验

1. `npm install && npm run dev` → http://localhost:3000
2. **大厅**：按「男生/女生都在玩」匹配搭子——对比纪岚的慵懒、小满的奶音、闻笙的高冷
3. **陪伴页**：和 TA 说话（开 🔊 语音，音色随性格不同）；点「🖥 桌面模式」弹出置顶小窗
4. **共历回放**：陪 TA 看一场 TI 真实比赛（推荐 Ame 斯温 11/0/3 翻盘局）
   - 观察**时机引擎**：战斗中零插话（右上角「打扰 0」）；关闭开关看对照组立刻暴露
   - 赶时间：点「跳到结算」
5. **结算「TA 变了」**：记忆卡沉淀 + 性格轴漂移（如 活跃+6 亲密+2），每一条都有因果理由
6. 回**陪伴页**：性格轴、演化日志、记忆库全部更新——TA 因为这场经历不一样了

## 架构

```
┌─ 数据层 ─────────────────────────────────────────────────┐
│ Valve 官方回放 → gem-dota 开源解析 → 事件流 JSON           │
│ （击杀/团战/经济差/出装/BP/聊天 · 离线打包 · OpenDota 可在线）│
└──────────────┬──────────────────────────────────────────┘
               ▼
┌─ 经历引擎（lib/aida-engine.ts）───────────────────────────┐
│ ① 事件流构建（以所选选手为"你"，双向视角相对性）             │
│ ② 时机引擎：死亡=天然窗口；战斗中→排队；结算后冲刷           │
│ ③ 情绪记忆库：高光/至暗/习惯/里程碑 ← 纯数据驱动、可审计     │
│ ④ 同行值计分 → 关系等级（初识→过命战友）                    │
└──────────────┬──────────────────────────────────────────┘
               ▼
┌─ 伙伴系统（lib/personas.ts + buddy-store.ts）─────────────┐
│ ① 人设卡：预设/自定义 · 外观 · 语气 · 语音参数              │
│ ② 性格五轴演化：evolveFromExperience 纯函数（因果可解释）    │
│ ③ 塑形边界（±10）防 OOC；演化日志全量留存                   │
│ ④ localStorage 持久化：记忆跨场次、关系跨会话               │
└──────────────┬──────────────────────────────────────────┘
               ▼
┌─ 交互层 ─────────────────────────────────────────────────┐
│ 回放播放器（10x/30x/60x）· 经济曲线 · 战斗日志              │
│ 聊天：模板人格脑（必能开口）+ LLM（可选，混元/DeepSeek/GLM） │
│ 语音：Web Speech TTS（音色随性格轴）+ STT 按住说话           │
│ 桌面：Document Picture-in-Picture 置顶小窗（降级页面浮窗）   │
└──────────────────────────────────────────────────────────┘
```

**架构判断**：时机判断用规则状态机（确定、可解释、可 A/B）；性格演化是纯函数（可审计）；
LLM 只做低频高价值的自由问答，人格+记忆+关系结构化注入、禁止编造经历，无 Key 自动降级——
每一句话都有数据来源，demo 现场必能跑。

## 三个核心设计判断

1. **情感来自共同经历，不来自对话质量。** 聊天是廉价的关系；把好感度锚定在真实行为事件上（见证击杀/患难/翻盘各自计分），刷聊天无法涨关系。
2. **陪伴的正确形态是"不打扰"。** 时机 > 频率 > 话术：死亡才是天然发言窗口，战斗中的事件排队到团战结算后再说。打扰度是一级指标，且做了可开关的对照组。
3. **性格成长必须可解释。** 每次演化都有因果日志（"见证翻盘 → 活跃+3 亲密+2"），玩家看得见 TA 为什么变成这样；塑形设 ±10 边界，防止把养出来的性格一键抹掉（防 OOC）。

## 评测框架

| 指标 | 定义 | 目标 | 状态 |
|---|---|---|---|
| 打扰度 | 战斗进行中的插话次数 | 时机引擎 ON = 0 | ✅ 自动化验证 |
| 记忆准确率 | 对历史经历提问的正确率 | ≥ 90% | ✅ 架构性保证 |
| 演化合理性 | 盲测「性格变化是否符合剧情」 | 认可率 > 80% | 演化因果全可解释 |
| 情感共鸣分 | 玩家对发言打分（-2~+2） | 均值 > +1 | 待小样本 |
| D7 回访率 | 有/无伙伴对照 | +10pp | 待测试 |

**复现**：`npm run test:engine`（时机/打扰/视角相对性/记忆卡）+ `npm run test:persona`（演化数学/人格脑/预设完整性）

## 商业化想象

免费增值（基础陪伴免费）→ Plus（语音 + 桌宠 + 记忆扩容）→ Pro（定制音色、人设工坊、限定联动伙伴）。
长期的想象是把搭子做成游戏平台的标配能力：从金铲铲陪你到无畏契约，跨游戏的持久陪伴记忆是平台级资产。页面里的会员方案是原型阶段的产品设计推演。
